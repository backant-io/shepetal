## 1. Features (user-visible)

- Text appears at the cursor in any app after push-to-talk ends. Insertion is a paste, not typing: the user's clipboard is put back afterwards.
- If nothing accepted the paste (no app pulled clipboard data), Flow can show a "failed paste" notification, and the last dictation can be pasted again later ("paste last text").
- Context-aware punctuation and casing: dictating mid-sentence lowercases the first letter, drops the trailing period when text follows the cursor, and adds a leading or trailing space as needed.
- In messaging apps the trailing period is dropped for short messages, depending on the chosen style (formal, casual, very casual).
- Selected text is replaced by the dictation. With command mode, the selection is the thing the command edits.
- Per-app styles: apps are bucketed (AI, Email, Work, Personal messaging, Other) and each bucket can have its own writing style. Emails can get a signature line ("written/spoken with Flow").
- Proper nouns visible on screen (names in the document, chat participants) are spelled correctly because the screen text is sent as ASR/LLM vocabulary.
- Developer features in Cursor/Windsurf/VS Code: file tagging (saying a file name inserts `@file` and accepts the editor's autocomplete) and recognition of variable names (identifiers visible in the editor are spelled as code).
- Terminals get plain text: no simulated keys, no special markers.
- Secure input (password fields, or any app holding Secure Event Input) blocks the paste, and Flow tells the user which app holds it.
- "Press enter" voice command: ending a dictation with it makes Flow paste, then press Enter once the paste succeeded (a `[PressEnterCommand]` log line at `main@4353172`). A first-time prompt asks the user to enable it.

## 2. How it works

### 2.1 Process split
Electron main (JS) decides *what* to paste; a bundled Swift helper app (`swift-helper-app-dist/Wispr Flow.app`) does all Accessibility (AX) reads, keystroke synthesis and pasteboard work. They talk over a JSON message API generated by quicktype (`index.js: HelperAPIRequest` / `HelperAPIResponse`). Relevant requests and their field names (full list in `helper-schema.txt`):

### 2.2 Insertion: clipboard + synthesized Cmd+V (primary path)
- Flow does **not** insert via `AXUIElementSetAttributeValue(kAXSelectedText/kAXValue)` for dictations. The only direct AXValue set in the helper is for a meeting-chat feature (`helper-strings.txt:8762`: a `ConsentChatMessage` log line reports that the AXValue write did not hold and that it pastes instead). The helper never calls `CGEventKeyboardSetUnicodeString` (0 call sites in the disassembly), so it never types text character by character. It calls `CGEventCreateKeyboardEvent` (22 sites), `CGEventSetFlags` (23), `CGEventPost` (14) and `CGEventPostToPid` (8): a modifier+key chord.
- Sequence, reconstructed from helper log strings:
  1. At dictation start the helper stores the focused AX element and its app (`StoreFocusedAppAndElement`; success and retry log lines at `helper-strings.txt:8837`-`8838`). This is how the paste lands in the original field even if focus moved while Flow's UI was up.
  2. On `PasteText`, it re-activates the stored app and refocuses the element. Fallbacks are explicit, each with its own log line (`helper-strings.txt:8823`-`8828`): paste into a fallback element, paste right after activating the app when no element can be focused, and a last-resort paste.
  3. It saves every pasteboard type currently on `NSPasteboard.generalPasteboard` (log line at `helper-strings.txt:10025`).
  4. It writes the text (plus an HTML flavour when `htmlText` is set, e.g. for Slack rich text or snippets), marking it with `org.nspasteboard.ConcealedType` so clipboard managers ignore it.
  5. **Delayed rendering** (helper class `DelayedClipboardProvider`, `NSPasteboardItemDataProvider`): the pasteboard item is promised, not filled. When the target app actually reads it, `pasteboard:item:provideDataForType:` fires. That is the success signal: the data request cancels the failure timer (`helper-strings.txt:10105`). If no app requests the data within a timeout (an `NSTimer` armed with a 1.0 s interval right before the timer-start log line at `helper-strings.txt:10089`; `fmov d0, #1.0` in the disassembly, moderate confidence), the paste is declared failed (`helper-strings.txt:10101`) and the JS side can show `failed-paste-notification`.
  6. Posts Cmd+V. Disassembly of the three paste sites (`helper-disasm.txt` around the three paste-done log literals, `helper-strings.txt:8824`, `8828` and `8830`): `CGEventSourceCreate(1 = HIDSystemState)`, `CGEventCreateKeyboardEvent(keycode 0x09, down)` and `(0x09, up)`, `CGEventSetFlags(0x100000 = Command)` on both, `CGEventPost(0 = kCGHIDEventTap)` for key-down, `usleep(5000)` (5 ms), then key-up. Keycode 9 is the physical ANSI V position and is hardcoded on the main path. On layouts where that key is not V (Dvorak), apps that match key equivalents by character may see Cmd+"." instead; Flow only resolves the layout for the remote-viewer path: it calls `TISCopyCurrentKeyboardInputSource`, `kTISPropertyUnicodeKeyLayoutData` and loops `UCKeyTranslate` over keycodes to find the one producing 'v' (0x76), next to the `ai.wispr.remote-viewer-paste` literal (disassembly around 0x100282e84 to 0x100283394). A second variant posts the same chord with `CGEventPostToPid` (targeted at one process). Cmd+C for the copy fallback is keycode 0x08; Tab for markers is 0x30 followed by a 50 ms sleep. If physical modifier keys are still held (common right after a PTT chord), it logs that (`helper-strings.txt:10047`) and `PasteAnalytics.modifierKeysDown` records it; there is a `CheckStaleKeys` request to detect stuck keys.
  7. **Clipboard restore**: the helper logs a restore scheduled 500 ms out, then the restore and its completion (`helper-strings.txt:10092`, `10027`, `10096`). With delayed rendering, the restore runs asynchronously after the data was served (`helper-strings.txt:10029`). If the saved clipboard has items that could not be put back exactly, a flow skips the clipboard path (`helper-strings.txt:8765`). Feature flag `disable-clipboard-restore` turns restore off.
- Variants behind feature flags (`index.js: FeatureFlags` schema): `shift-insert` (Shift+Insert as the paste chord; which apps get it is not visible statically), `remote-viewer-paste` with `pasteDelayMs` (remote desktop / screen-sharing viewers, which need a delay so the clipboard syncs to the remote side; the helper logs the clipboard offer, then the posted chord, `helper-strings.txt:10034` and `10037`), `windows-key-up-simulation`.
- Special markers: the JS can embed `{{TAB}}` and `{{BREAK}}` in the text. The helper splits on them and posts real Tab / break keys between paste chunks (`helper-strings.txt:8855`, `10030`). This is how file tagging accepts an IDE autocomplete. Markers are stripped before paste when the focused element looks like a terminal (`index.js: "includes Terminal"`).
- The text handed to the OS is post-processed: HTML stripped, a trailing boundary space turned into a non-breaking space (so apps that trim trailing ASCII spaces keep it), markers removed (ax-inspect-lib.mjs comments on `pastedText`, referencing an internal `pastePolicy.ts`).
- `shouldPressEnterAfterPaste` and `shouldMoveCursorAfterPaste` are flags returned by the formatter step (`index.js: shouldPressEnterAfterPaste`). After a successful `PasteOutcome`, JS sends `SimulateKeyPress` Enter, or Up then Left to move the caret (used by some formatting routes).
- Failure recovery: when `PasteOutcome.success` is false, JS runs a one-shot recovery that shows a notification holding the dictated text (or a generic "paste failed" one), with an action that sends `CancelPaste` so the helper drops its pending delayed-rendering promise (`index.js: pasteFailureRecoveryRan`; the `[CancelPaste]` log line at `main@6457959`).

### 2.3 Post-paste verification and edit tracking
- After paste, the helper re-reads the focused element and checks the dictated text is present: verdicts `verified`, `verified_before_after` (box equals before + paste + after), `not_found`, `skipped` (e.g. `textbox_too_long`) (`DictatedTextVerification`, ax-inspect-lib.mjs).
- It then observes the field for up to ~60 s (ax-inspect-lib.mjs: "observation_window_elapsed ... 60s fallback") and reports the user's final edits (`UpdateEditedText`: edited text, normalized Levenshtein to the dictation, why observation ended, last keystroke category). This most likely feeds the auto-learned dictionary (inference: the payload carries dictated vs final text and an edit distance). A global CGEventTap supplies the keystroke categories; per the inspector comments the helper forwards no keycodes and no characters, only categories (send, delete, undo, cut).

### 2.4 Context capture (what is read)
1. **App identity** (helper `AppInfoUpdate`): app name, bundle id, window title, and for browsers the page URL found by walking to the `AXWebArea` (`helper-strings.txt:10148`). It also detects coding CLI agents running in terminals (`codingCliAgent` + confidence, flag `coding-cli-detection`).
2. **Textbox** (`TextBoxInfo`): full contents, text before the cursor, selected text, text after, editable flag. Read through `AXFocusedUIElement`, `AXValue`, `AXSelectedTextRange`/`AXSelectedTextRanges`, `AXStringForRange`, `AXNumberOfCharacters`. The helper climbs or descends the tree when the focused element is a static text or a text area with inline images (`helper-strings.txt:9535`-`9537`). If the selection range is unreliable it searches the selected string in the contents (the search fallback logs at `helper-strings.txt:9558`).
3. **Selected text via copy** (`GetSelectedTextViaCopy`, `copyMode`): fallback that posts Cmd+C (keycode 0x08) and reads the pasteboard. JS uses it when AX is not functioning or reports no selection (log line at `main@4248452`), e.g. for the "ask/search about <selection>" voice actions that append the selection to a query.
4. **Document context** (`AppContextUpdate`), two alternatives compared side by side in the inspector:
   - `nearestTexts`: text gathered by walking the AX tree around the focused element.
   - `markerRangeStringValue`: the whole document text via WebKit/Chromium text markers (`AXStartTextMarker`, `AXTextMarkerRange`, `AXAttributedStringForTextMarkerRange`), no traversal; empty in apps without marker support.
   - `axHTML`: an HTML rendering of the AX tree (roles, frames, focused node) used as `content_html`; enabled for dev/internal and some flows (`SetAccessibilityTreeCapture`).
5. **Words for vocabulary** (`appContext.axParsedWords`, `vsCodeFileNames`, `vsCodeVariableNames`): tokens mined from the above and sent as ASR hints.
6. **Screen OCR**: exists but is off by default (`shouldOCRScreenCapture:!1` in the default prefs). Pref `shouldOCRScreenCapture` (and `useAxContext`) gates a screenshot that is posted to the cloud endpoint `/llm/ocr` (`index.js: extractProperNounsFromScreenCapture`) and returns `ocrParsedWords`. In the streaming protobuf `flow_api.v1.Context.screenshot` is always sent as an empty byte array in this build.
7. **Focus changes during dictation**: `FocusChangeDetector` re-captures the textbox when focus moves mid-dictation and again at PTT stop (flags `focus-change-detector-enabled`, `focus-change-detector-app-change`).
8. **Conversation identity**: a helper component logged as the conversation selector builds a `conversationId` from the window title components of chat apps (`helper-strings.txt:10119`-`10126`). It is attached to the context and history so tone and style can follow the thread.
9. **Electron / Chromium apps**: the helper sets `AXManualAccessibility` on Electron apps (`helper-strings.txt:9801`) and knows `AXEnhancedUserInterface`; both make Chromium build its AX tree so the reads above work in Slack, VS Code, Cursor, Notion desktop, etc.
10. **Limits**: textbox before/after/contents sent to the server are cut to `MAX_TEXTBOX_CONTENTS_LENGTH` = 500 chars at a word boundary (before keeps the tail, after keeps the head) (`index.js: limitedTextboxContents`). The server-side proper-noun extractor keeps the first and last 2,500 chars once input passes 5,000 (ax-inspect-lib.mjs comment). Terminal captures contain NUL-padded cells, mapped to spaces.
11. Context is skipped entirely if `useAxContext` is off, and for Flow's own windows on Windows.

### 2.5 How context changes the text
- Client-side context-aware pasting (log line at `main@4245153`). Uses the last line of `beforeText` and the first line of `afterText`:
  - lowercases the first letter when the cursor is mid-sentence (and the first word is not a known name or dictionary word);
  - strips trailing `.!?` when text follows that continues the sentence;
  - prepends a space if the char before the cursor is not whitespace; appends one if the next char starts a word;
  - with a selection, matches the selection's casing, its trailing punctuation, and its leading/trailing spaces.
  - Notion: skips the adjustment when the before text looks like placeholder text.
- Messaging apps (`index.js: isMessagingApp`, `isSlack`, bundle/URL lists): removes the trailing period of short messages; formal style keeps it, casual up to 10 sentences, very casual always.
- Server-side formatting gets the context (`flow_api.v1.Context`: `app{name,bundle_id,url,type}`, `textbox{contents,before_text,selected_text,after_text}`, `vocabulary{screen_content_ax, screen_content_ocr, variable_names, file_names}`, `content_text`, `content_html`, `session_dictation_apps`, `conversation{participants,messages}`). The LLM uses it for tone, spelling of names, and continuing the existing text.

### 2.6 Per-app styles
- App classification (`index.js`, two functions over lowercase bundle-id / URL prefix lists, first match wins):
  - Personalization bucket: AI (ChatGPT, Claude, Codex, Cursor, Windsurf, VS Code, Perplexity, Warp, Ghostty desktop apps plus web AI sites such as chatgpt.com, claude.ai, gemini, v0, lovable, replit) -> Email (Apple Mail, Outlook, Gmail, Superhuman, Mimestream, Thunderbird, Airmail, and web mail prefixes) -> Work (Slack, Teams, Zoom, Webex, LinkedIn, Mattermost, Zulip, RingCentral...) -> Personal messaging (Messages, WhatsApp, WeChat, Messenger...) -> Document (Notion, Google Docs, Word, Pages, Obsidian, Bear, Excel, Linear, Figma...).
  - Format type (`manuallySetAppType` overrides it): AI, Email, or Other; terminals are forced to Other.
- `flow_api.v1.StyleConfig`: `general_style` (one each for `personal`, `work`, `email`, `other`), `override_style`, `tagging` (Slack @-mention tagging, flag `SlackTagging`), `signature` (email sign-off variants), `editing_strength` (mapped from the "auto cleanup" level: verbatim, light, medium).
- Style values per bucket (`index.js` enum): `formal`, `casual`, `veryCasual`, `excited`, `genz` (treated as `veryCasual` locally), `default`. Buckets: `personal`, `work`, `email`, `other`. Locally only the messaging period rule reads the style; the rest is applied by the server LLM.
- "Tone match" (`internal.isToneMatchEnabled`) and "MyVoice" (a `[MyVoice]` log line at `main@3758580` sends the style config) are server-side style personalization.

### 2.7 Developer mode (Cursor / Windsurf / VS Code)
- Bundle ids `com.todesktop.230313mzl4w4u92` (Cursor), `com.exafunction.windsurf`, `com.microsoft.VSCode`; JetBrains is also listed for some features.
- The helper reads open file names and the chat textarea from the IDE's AX tree (`CursorContextUpdate.fileNames`, `textAreaContents`; flag `cursor-integration`). File names and visible identifiers go to the server as `file_names` / `variable_names`.
- "File tagging": when the dictation mentions an open file, JS rewrites it to `@<name>{{TAB}}` (with a `{{BREAK}}` after `@`), so the IDE's `@` picker opens, the name is pasted, and Tab accepts the suggestion (`index.js: cursorFormatting`, `main@4292717`). A guard checks the last app is in the IDE list and is not VS Code (`index.js: "com.microsoft.VSCode"!==e`); it appears to gate the simulated-key path, not verified. Terminals and focused elements described as "terminal" get the markers stripped.
- Variable names: a local regex-based symbol miner (log line at `main@4462513`) guesses the language from pattern scores, then extracts variable, class and function names from the captured editor text (caps 100/50/50, drops keywords and names over 50 chars). These go to the server as `variable_names` so identifiers come back spelled as in the code.
- File names seen in Cursor are cached per session (`persistentAppContext.cursorFileNames`) and merged into the vocabulary; Slack gets the same treatment with names seen in Slack (`persistentAppContext.slackContext`).

### 2.8 Special cases
- **Terminals** (Terminal, iTerm2, Warp, Ghostty, kitty, Alacritty, Hyper): no `{{TAB}}`/`{{BREAK}}` keys, plain paste; NUL-padded AX text decoded.
- **Secure fields**: `AXSecureTextField` is recognised; `SecureInputMonitor` polls `IsSecureEventInputEnabled` and `kCGSSessionSecureInputPID` to name the app holding secure input, and raises `PasteBlocked`.
- **Browsers**: URL lookup via `AXWebArea`; Chrome variants listed. Google Docs appears only as an app-classification entry (`url:"docs.google.com"`, grouped with Notion, Word, Pages, Obsidian as document apps). No Docs-specific insertion code was found: it gets the normal Cmd+V paste. Context reads in Docs depend on Chrome exposing its AX tree; marker-range text is the path that can work there.
- **No editable field**: for extension/route pastes, if the textbox could not be read or is not editable, Flow shows a "void dictation" notification holding the text instead of pasting into nothing (`index.js: sendVoidDictationNotification`). Normal dictations still paste and rely on the 1 s delayed-rendering check plus `failed-paste-notification`.
- **Slack**: HTML pasteboard flavour for rich text (`helper-strings.txt:9566`).
- **Notion**: placeholder detection.
- **Remote desktop viewers**: delayed paste chord (`remote-viewer-paste`).

### 2.9 ax-inspect*.mjs (dev tools shipped by accident)
`ax-inspect.mjs` (one-shot), `ax-inspect-server.mjs` (live list), `ax-inspect-lib.mjs` (shared). They read the local unencrypted `flow.sqlite` History table plus dev-only JSONL sidecars in the logs dir (paste, noun, textbox, verify, event, edit, context traces) and render an HTML timeline per dictation: what the client captured, what was sent to the server, what came back, what was pasted, and what the user edited. Sidecars are written only when `internal.shouldSaveAxText` is on or the app is unpackaged (`index.js: shouldSaveAxText`). Useful for us as a blueprint for a local debugging view; nothing to copy.

## 3. Local vs cloud

| Step | Where |
|---|---|
| AX reads, focus restore, pasteboard save/restore, Cmd+V, verification, edit observation | Local (Swift helper) |
| Context-aware casing/spacing/punctuation tweak, messaging period removal, file-tag rewrite, marker stripping | Local (Electron JS) |
| ASR + LLM formatting using app/textbox/vocabulary/style context | Cloud (gRPC `flow_api.v1.Request{init,context,payload,commit}`) |
| Proper-noun extraction from nearest text (`/llm/extract_asr_words`, gpt-4o-mini per inspector comment) | Cloud |
| Screen OCR (`/llm/ocr`) when enabled | Cloud |
| Textbox contents, before/after text, nearest text, AX HTML | Leave the machine as part of context |

## 4. What shepetal must build

### Mac
Goal product rule 8 overrides [M1] and [M2] below. shepetal stores the focused app and window at dictation start and pastes only if that same window is still focused when the text is ready; it never refocuses or reactivates the original app. When focus moved, Secure Input is on, or the paste does not land, the text stays on the clipboard as plain text (with the Concealed and Transient markers) and the old clipboard is not restored; the hint next to 🤫 says to press ⌘V.

- [M1] Helper with Accessibility permission: store focused element + pid at PTT start; restore focus before insert.
- [M2] Insert via pasteboard + CGEvent Cmd+V. Save all pasteboard items/types first (skip the clipboard path, or warn, when they cannot be restored, e.g. file promises). Write the text with `org.nspasteboard.ConcealedType` (what Flow uses) and `org.nspasteboard.TransientType` (our addition) as a lazy `NSPasteboardItemDataProvider` item; treat the provider callback as "paste landed". Declare failure if no read within ~1 s (Flow's value), keep the text in a "paste failed, copy it" notification, and restore the clipboard ~500 ms after the read (Flow's value).
- [M3] Resolve the keycode for 'v' in the current layout (`UCKeyTranslate` reverse lookup), defaulting to 9; post key-down/up with only the Command flag set (so held PTT modifiers do not leak into the chord) via `kCGHIDEventTap`, a few ms apart; detect stuck modifiers first.
- [M4] Optional direct AX insert (`kAXSelectedTextAttribute` set) as a no-clipboard mode for native Cocoa fields, verified by re-reading `kAXValue`; fall back to paste when it does not stick.
- [M5] Read context: app name, bundle id, window title, browser URL via `AXWebArea`/`AXURL`, textbox before/selected/after via `AXSelectedTextRange` + `AXStringForRange`; set `AXManualAccessibility` on Electron apps.
- [M6] Detect secure input (`IsSecureEventInputEnabled`, `AXSecureTextField`) and refuse to paste, with a message.
- [M7] Context-aware casing/spacing/punctuation locally (all local in Flow anyway, cheap to replicate).
- [M8] Terminal list (Terminal, iTerm2, Warp, Ghostty, kitty, Alacritty, Hyper, WezTerm): plain paste only, no key markers.
- [M9] Marker protocol between formatter and inserter: `{{TAB}}` (post Tab, then wait ~50 ms) and a break marker (split the paste), stripped for terminals. Needed for IDE file tagging.
- [M10] "Press enter" trailing voice command: strip it from the text and post Return only after the paste was confirmed.
- [M11] Post-paste verification: re-read `kAXValue` of the stored element and look for the inserted text (verdicts: verified / not found / skipped when too long).

### iPhone
- [I1] Keyboard extension inserts with `textDocumentProxy.insertText`; no clipboard. Replace selection by inserting (the proxy replaces the selected range).
- [I2] Context: `documentContextBeforeInput`, `documentContextAfterInput`, `selectedText` (iOS 11+), `documentIdentifier`; host app identity is not available, so app-type styles need a manual per-app setting or a keyboard-type heuristic (`keyboardType`, `returnKeyType`, `textContentType`).
- [I3] Secure fields: iOS swaps to the system keyboard automatically; nothing to do.
- [I4] Apply the same local casing/spacing rules from the before/after context.
- [I5] iOS gives only a short window of context (usually the current paragraph or a few hundred chars around the caret) and nothing outside the text field: no window title, no screen text, no OCR. Vocabulary from the screen is not possible; rely on the user dictionary.
- [I6] Markers: `{{TAB}}` has no keyboard-extension equivalent (`insertText("\t")` inserts a tab character, it does not accept an autocomplete); drop file tagging on iPhone. "Press enter" maps to `insertText("\n")`, which sends in most chat apps.

### Linux
- [L1] Wayland: `wtype` (virtual-keyboard protocol, wlroots compositors) for direct typing; `ydotool` (uinput, needs the daemon and permissions) as a compositor-independent fallback; clipboard path with `wl-copy` + Ctrl+V (Ctrl+Shift+V in terminals). GNOME/KDE do not support the virtual-keyboard protocol, so on those use the clipboard + `ydotool` or the XDG RemoteDesktop portal.
- [L2] X11: `xdotool type --clearmodifiers` for short text; for long text `xclip`/`xsel` + `xdotool key ctrl+v` (ctrl+shift+v or Shift+Insert for terminals). Save and restore both CLIPBOARD and PRIMARY.
- [L3] Context: AT-SPI2 (`Accessible.Text` get_text / get_caret_offset / get_selection) for before/after/selected where apps support it; active window class/title via `_NET_ACTIVE_WINDOW` (X11) or compositor IPC (sway/hyprland) on Wayland.
- [L4] Terminal detection by window class (gnome-terminal, konsole, kitty, alacritty, wezterm, foot) to pick the paste chord.
- [L5] Linux has no "data was requested" signal comparable to macOS lazy pasteboard for most tools; use a fixed restore delay (start at 500 ms, make it configurable) and verify via AT-SPI where possible.
- [L6] `xdotool type` and `wtype` mishandle some non-ASCII text and keyboard layouts; prefer the clipboard path for anything beyond short ASCII.

### All platforms
- [A1] Keep context local: our formatter runs on device, so before/after text never needs to leave the machine. Make capture opt-out per app.
- [A2] Per-app style buckets (AI, email, work chat, personal chat, other) keyed by bundle id / URL prefix / window class, user-overridable.
- [A3] Dev mode: optional `@file` + Tab insertion for Cursor/Windsurf using the markers approach; skip for terminals.
- [A4] Post-insert verification by re-reading the field, used only to detect failed inserts.
- [A5] Port the local text rules: mid-sentence lowercasing, trailing punctuation removal before following text, smart leading/trailing space, selection-shape matching, messaging-app period removal by style, trailing-space-to-NBSP on paste.
